```
model.onnx     24클래스 YOLOv8n int8 ONNX (3.3MB)
```

**저장소에 함께 들어 있습니다.** clone 해서 `npm install` 하면 모델까지 갖춰지므로
따로 구할 것이 없습니다. `modelPath()` 가 이것을 가리키고, 경로를 주지 않으면 CLI 가
이것을 씁니다.

```js
import { modelPath, modelBytes, readClassMap } from "naranhi";
readClassMap(modelBytes()).get(7);   // 'person'
```

## 클래스 번호를 숫자로 박지 마세요

클래스 이름은 **모델 metadata 에 들어 있습니다.** 원본 29클래스에서 5쌍이 병합돼
24개가 되면서 **번호가 밀렸습니다** (`person` 8→7, `bollard` 15→12).
`readClassMap(modelBytes())` 로 읽거나 결과의 `class_name` 을 쓰세요.

## 인식 모듈 팀의 파일입니다

여기서 다시 학습하거나 고치지 않습니다. 다음 버전은 인식 모듈에서 받습니다.
[nrh-detector 공개 저장소](https://github.com/J4VIS-2026/nrh-detector)에서 소스와 배포
버전을 관리합니다.

## 원본과 다른 점 하나 — metadata 의 학습 데이터 경로를 지웠습니다

인식 모듈이 준 원본은 `description` 에 만든 사람 PC 의 경로를 담고 있었습니다
(`G:\ai_ws\...\street.yaml`). 인식 모듈 문서가 **미해결 항목**으로 밝히고 "공개 저장소에
올리기 전에 지워야 한다"고 적은 것이라 지웠습니다.

```
전  ...model trained on G:\ai_ws\yolo_test\4.yolo_all_data_train_test\...\street.yaml
후  ...model trained on the AI Hub sidewalk walking video dataset
```

**같은 길이로 덮어썼습니다.** ONNX 는 protobuf 라 문자열 길이를 바꾸면 감싼 길이도
고쳐야 하고, 거기서 틀리면 파일이 안 열리거나 더 나쁘게는 열리는데 값이 어긋납니다.
길이가 같으면 그런 계산이 아예 없습니다. 파일 크기는 3,503,070바이트 그대로입니다.

**metadata 를 통째로 지우지 않았습니다** — 클래스 맵이 같은 곳에 있어서 날리면 인식이
**조용히** 죽습니다.

인식 모듈 쪽 원본 파일은 그대로이니 **그쪽에도 알려야 합니다.**
